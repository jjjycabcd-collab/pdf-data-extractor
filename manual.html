PDF Meta-Extractor

PDF 메타데이터 추출 및 상호작용 어노테이션 에디터

본 시스템은 PDF 문서에서 핵심 메타데이터를 효율적으로 추출하고, 구조화된 학습/구축 데이터를 생성하기 위해 개발된 웹 기반 상호작용 도구입니다. 수작업을 최소화하고 데이터 정확도를 극대화합니다.

⚙️ 프로그램 처리 절차

파이프라인의 각 단계를 클릭하여 상세 동작 메커니즘을 확인하세요.

🛠️ 프로그램 사용 기술 및 모듈 분석

각 기술 스택을 선택하여 해당 모듈의 역할과 시스템 내 핵심 성능 지표(개념도)를 확인하세요.

파이썬 기반의 빠르고 직관적인 웹 UI 구현 및 상태 관리. PDF 렌더링 이미지 위에서 직접 Bbox를 그리는 핵심 뷰어 역할을 수행합니다.

⚠️ 프로그램 한계점 및 개선 방안

시스템 최적화 과정에서 발생한 아키텍처 한계와 이를 극복하기 위한 향후 대안입니다.

💾

메모리 의존성 (OOM 리스크)

현상: 업로드된 PDF 파일 전체를 서버 메모리(session_state)에 로드하여 처리합니다.

한계: 500페이지 이상 대용량 파일 또는 다중 접속 시 Out Of Memory 에러 발생 가능성이 존재합니다.

💡 개선대안: 임시 폴더(tempfile) 저장 및 페이지 단위 스트리밍 로드 아키텍처 도입

⚡

OCR 처리 속도와 OS 의존성

현상: Tesseract OCR 호출 시 별도의 프로세스가 실행됩니다.

한계: Host OS에 Tesseract 바이너리 설치가 강제되며, 다중 Bbox 처리 시 속도 저하 및 스캔 품질에 따른 인식률 편차가 있습니다.

💡 개선대안: 비동기 큐잉 시스템 도입 또는 클라우드 기반 OCR API 병행 사용

🎯

오토피팅(Auto-fitting) 오작동

현상: 텍스트 레이어 좌표를 참조하여 박스를 정밀하게 자동 조절합니다.

한계: 텍스트 레이어가 물리적 이미지와 틀어진 불량 PDF나 복잡한 배경 이미지의 경우 엉뚱한 위치로 피팅될 수 있습니다.

💡 개선대안: 레이어 불일치 임계값 감지 로직 추가 및 오토피팅 수동 강제 오버라이드 기능

🔄

단방향 저장 구조 (영속성 부재)

현상: 추출된 데이터는 브라우저 세션 유지 중에만 존재하며 최종 JSON 다운로드로 마무리됩니다.

한계: 새로고침이나 예기치 않은 종료 시 작업 내역이 모두 소실됩니다.

💡 개선대안: IndexedDB를 활용한 브라우저 로컬 중간 저장 또는 경량 DB 연동
